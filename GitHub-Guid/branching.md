## آموزش Branching در Git

 ### 1. شاخه (Branch) چیست؟

در Git، شاخه (Branch) یک مسیر مستقل برای توسعه و ایجاد تغییرات در پروژه است.

با استفاده از Branch می‌توان بدون ایجاد تغییر مستقیم در شاخه اصلی پروژه (main)، قابلیت‌های جدیدی اضافه کرد یا بخش‌هایی از پروژه را ویرایش کرد.

برای مثال، فرض کنید اعضای یک تیم در حال طراحی یک وب‌سایت هستند. یک نفر مسئول طراحی صفحه ورود (Login)، نفر دیگر مسئول طراحی صفحه ثبت‌نام (Register) و نفر سوم مسئول طراحی صفحه اصلی (Home) است.

هر عضو می‌تواند روی یک Branch جداگانه کار کند و تغییرات خود را بدون تأثیرگذاری بر کار دیگران انجام دهد. در پایان، تغییرات هر شاخه می‌توانند با شاخه اصلی ادغام شوند.

### 2. چرا از Branch استفاده می‌کنیم؟

استفاده از Branch مزایای زیادی دارد:

- جلوگیری از تغییر مستقیم روی شاخه اصلی (main)
- امکان همکاری هم‌زمان اعضای تیم
- آزمایش قابلیت‌های جدید بدون تأثیر بر نسخه اصلی
- مدیریت بهتر تغییرات پروژه
- کاهش احتمال ایجاد مشکل در کد اصلی

### 3. مشاهده Branchها

برای مشاهده شاخه‌های محلی موجود در پروژه از دستور زیر استفاده می‌کنیم:

```
git branch
```

شاخه‌ای که علامت ستاره (*) کنار آن قرار دارد، شاخه فعال فعلی است.

برای مثال، خروجی زیر را در نظر بگیرید:

 ```
  main

  feature-login

* feature-register
```

در این مثال، سه شاخه وجود دارد و شاخه feature-register فعال است.

### 4. ساخت Branch جدید

برای ایجاد یک شاخه جدید از دستور زیر استفاده می‌شود:

```
git branch branch-name
```

به جای branch-name نام دلخواه شاخه قرار می‌گیرد.

مثال:

```
git branch feature-login

```

این دستور شاخه‌ای به نام feature-login ایجاد می‌کند، اما کاربر را به آن منتقل نمی‌کند.

برای ساخت یک شاخه جدید و ورود هم‌زمان به آن می‌توان از دستور زیر استفاده کرد:
```
git switch -c feature-profile
```

این دستور هم شاخه جدید را ایجاد می‌کند و هم کاربر را به آن منتقل می‌کند.

### 5. جابه‌جایی بین Branchها

برای رفتن از یک شاخه به شاخه دیگر از دستور زیر استفاده می‌کنیم:

```
git switch branch-name
```

مثال:
```
git switch main
```
با اجرای این دستور، کاربر به شاخه اصلی پروژه منتقل می‌شود.

برای ورود به شاخه دیگری نیز می‌توان نوشت:


```
git switch feature-login
```

نکته: اگر تغییرات ثبت‌نشده‌ای داشته باشیم که با تغییر شاخه تداخل داشته باشند، Git ممکن است اجازه جابه‌جایی ندهد.

برای بررسی وضعیت پروژه از دستور زیر استفاده می‌کنیم:

```
git status
```

### 6. تغییر نام Branch

برای تغییر نام شاخه فعلی از دستور زیر استفاده می‌شود:

```
git branch -m new-name
```

مثال:

```
git branch -m feature-user-login
```

با اجرای این دستور، نام شاخه فعلی به feature-user-login تغییر می‌کند.

### 7. حذف Branch

برای حذف یک شاخه محلی که دیگر به آن نیاز نداریم، از دستور زیر استفاده می‌کنیم:

```
git branch -d branch-name
```

مثال:
```
git branch -d feature-login
```

این دستور در حالت عادی شاخه‌ای را حذف می‌کند که تغییرات آن ادغام شده باشند.

اگر بخواهیم شاخه‌ای را حتی در صورت ادغام‌نشدن تغییرات آن حذف کنیم، می‌توانیم از دستور زیر استفاده کنیم:

```
git branch -D branch-name
```

توجه: استفاده از دستور بالا ممکن است باعث از دست رفتن تغییرات ادغام‌نشده شود؛ بنابراین باید با احتیاط از آن استفاده کرد.

### 8. مثال عملی: ایجاد یک Branch برای انجام وظیفه

فرض کنید در یک پروژه قصد داریم قابلیت ورود کاربران (Login) را اضافه کنیم.

ابتدا به شاخه اصلی پروژه می‌رویم:

```
git switch main
```

سپس یک شاخه جدید برای انجام این وظیفه ایجاد می‌کنیم:

```
git switch -c feature-login
```

حالا تغییرات مربوط به قابلیت ورود کاربران را در فایل‌های پروژه انجام می‌دهیم.

پس از ایجاد یا ویرایش فایل‌های موردنظر، وضعیت پروژه را بررسی می‌کنیم:

```
git status
```

سپس فایل‌های تغییرکرده را برای ثبت آماده می‌کنیم:

```
git add .
```

تغییرات را با یک پیام مناسب ثبت می‌کنیم:

```
git commit -m "Add login feature"
```

اکنون تغییرات ما در شاخه feature-login ثبت شده‌اند و شاخه اصلی مستقیماً تغییر نکرده است.

برای مشاهده شاخه‌ها می‌توانیم از دستور زیر استفاده کنیم:

```
git branch
```

در نهایت، پس از بررسی و تأیید تغییرات، می‌توان آن‌ها را با شاخه اصلی ادغام کرد. نحوه انجام این کار در فایل آموزش Merging توضیح داده شده است.

### 9. نکات مهم در استفاده از Branch

- بهتر است برای هر وظیفه یا قابلیت جدید یک Branch جداگانه ایجاد کنیم.
- نام Branch باید کوتاه، واضح و مرتبط با وظیفه باشد؛ مانند feature-login یا fix-header.
- بهتر است تغییرات مستقیماً روی شاخه اصلی (main) انجام نشوند.
- قبل از جابه‌جایی یا حذف شاخه‌ها، وضعیت پروژه را با دستور git status بررسی کنیم.
- ایجاد Branch به‌تنهایی تغییرات را به GitHub ارسال نمی‌کند. برای ارسال شاخه به
مخزن آنلاین باید از دستور `git push` استفاده کنیم.

### نتیجه گیری

قابلیت Branching (شاخه‌بندی) یکی از ویژگی‌های مهم Git است که به برنامه‌نویسان و اعضای تیم اجازه می‌دهد تغییرات خود را به‌صورت مستقل از یکدیگر انجام دهند و مدیریت کنند. استفاده صحیح از شاخه‌ها باعث افزایش نظم پروژه، جلوگیری از تداخل تغییرات و بهبود همکاری بین اعضای تیم می‌شود.
